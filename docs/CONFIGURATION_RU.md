# Настройка CAPE / Procmon

Расширение WebUI читает исходный файл:

`storage/analyses/<TASK_ID>/aux/procmon.xml`

Миграция базы данных CAPE не требуется. Для отображения событий UI не зависит от legacy-объекта Procmon processing.

## Включение сбора Procmon

Используйте механизм конфигурации, принятый в вашей установке CAPE. В разных ревизиях и развёртываниях конфигурация может управляться по-разному; важно, чтобы итоговая конфигурация включала Procmon auxiliary.

Нужно включить гостевой модуль Procmon:

```ini
[auxiliary_modules]
procmon = yes
```

Также рекомендуется оставить включённым processing-модуль:

```ini
[procmon]
enabled = yes
```

## Размер загрузки ResultServer

Procmon XML легко может превышать 100 MB. Убедитесь, что эффективный лимит ResultServer больше ожидаемого размера XML. Пример для лаборатории с достаточным запасом диска:

```ini
[resultserver]
upload_max_size = 500000000

[processing]
analysis_size_limit = 500000000
```

Точная логика size-limit параметров может отличаться между версиями CAPE. Если analyzer пишет, что загрузка успешна, но `aux/procmon.xml` на хосте отсутствует, проверьте установленный код ResultServer и его логи.

## Объём собираемых событий

Слишком широкий профиль Procmon быстро создаёт огромные журналы. В тестовой лаборатории нефильтрованный PML вырос примерно до 2.5 GB за несколько минут. После применения узкого PMC-профиля и включения **Drop Filtered Events** тот же тип анализа давал примерно 100–150 MB.

См. `extras/procmon-filter/FILTERS.md`.

## Необязательный stability patch для auxiliary Procmon

`extras/install_procmon_stability_fix.py` **не требуется для работы WebUI**. Он предназначен для старых ревизий CAPE, где Procmon auxiliary может зависать при остановке либо применять PMC только во время экспорта.

Патч добавляет ограниченные таймаутами запуск, остановку и экспорт, загружает PMC в начале захвата и не даёт Procmon блокировать завершение других auxiliary collectors. Installer специально отказывается патчить неизвестную ему версию исходного файла.

Не применяйте этот патч вслепую к новым версиям CAPE: сначала проверьте, не реализовано ли уже аналогичное поведение upstream.
